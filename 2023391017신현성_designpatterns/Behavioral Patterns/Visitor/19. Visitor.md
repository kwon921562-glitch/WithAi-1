# Visitor Pattern

> **카테고리:** Behavioral Patterns (행동 패턴)  
> **학습 순서:** 19/22

---

### 1. 한 줄 요약

**기존 객체 구조를 크게 수정하지 않고, 여러 종류의 객체에 새로운 작업을 추가하는 패턴이다.**

### 2. 사용하는 이유

Enemy, NPC, Item처럼 서로 다른 객체들에 저장, 디버그 출력, 통계 계산 같은 새 기능을 계속 추가해야 할 때 각 클래스에 기능을 계속 넣으면 책임이 많아진다. Visitor가 작업을 외부로 분리한다.

### 3. 핵심 구조

- **Element**: 방문을 허용하는 객체
- **Visitor**: 각 Element 종류에 수행할 작업 정의
- **Concrete Visitor**: 실제 새 작업 구현
- **accept(visitor)**: Visitor를 받아 자신의 타입에 맞는 처리를 요청

### 4. 동작 과정

1. Visitor를 만든다.
2. Element의 `accept()`를 호출한다.
3. Element가 Visitor의 자신에게 맞는 함수를 호출한다.
4. Visitor가 그 타입에 맞는 작업을 수행한다.

### 5. 게임 개발 예시

Enemy와 Item을 대상으로 DebugVisitor를 만들어 각 타입별 정보를 출력할 수 있다. 나중에 SaveVisitor를 추가해도 Enemy와 Item의 핵심 구조를 크게 수정할 필요가 없다.

### 6. 간단한 Lua 예제

```lua
local DebugVisitor = {}
function DebugVisitor:visitEnemy(enemy)
    print("Enemy HP:", enemy.hp)
end
function DebugVisitor:visitItem(item)
    print("Item Name:", item.name)
end

local Enemy = { hp = 100 }
function Enemy:accept(visitor)
    visitor:visitEnemy(self)
end

local Item = { name = "Potion" }
function Item:accept(visitor)
    visitor:visitItem(self)
end

Enemy:accept(DebugVisitor)
Item:accept(DebugVisitor)
```

### 7. 장점

- 기존 객체에 새 작업을 계속 넣지 않아도 된다.
- 관련 작업을 Visitor 하나에 모을 수 있다.
- 객체 종류별 처리 방식을 분리하기 좋다.

### 8. 단점

- 새로운 Element 종류를 추가하면 Visitor들도 수정해야 할 수 있다.
- 객체 내부 데이터에 접근해야 할 때 캡슐화가 약해질 수 있다.
- 처음 접하면 구조가 어려운 편이다.

### 9. 핵심 키워드

`방문`, `새 연산`, `기존 구조 유지`, `Element`, `Visitor`

### 10. 헷갈리기 쉬운 패턴

Iterator가 **요소를 순회하는 방법**에 관심이 있다면 Visitor는 **각 요소에 어떤 작업을 할지**에 관심이 있다.
