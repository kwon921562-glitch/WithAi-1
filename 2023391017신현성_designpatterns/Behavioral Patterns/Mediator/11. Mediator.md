# Mediator Pattern

> **카테고리:** Behavioral Patterns (행동 패턴)  
> **학습 순서:** 11/22

---

### 1. 한 줄 요약

**여러 객체가 서로 직접 통신하지 않고 중앙의 중재자 객체를 통해 통신하게 하는 패턴이다.**

### 2. 사용하는 이유

객체들이 서로 직접 참조하면서 메시지를 주고받으면 연결 관계가 거미줄처럼 복잡해진다. Mediator가 중앙에서 통신을 관리하면 각 객체는 다른 객체를 자세히 몰라도 된다.

### 3. 핵심 구조

- **Mediator**: 객체들 사이의 통신을 중재
- **Colleague / Component**: Mediator를 통해 다른 객체와 상호작용하는 객체

### 4. 동작 과정

1. Component가 어떤 사건을 Mediator에게 알린다.
2. Mediator가 사건을 해석한다.
3. 필요한 다른 Component에게 명령이나 알림을 전달한다.
4. Component끼리는 서로 직접 참조하지 않는다.

### 5. 게임 개발 예시

인벤토리 UI에서 아이템을 선택하면 ItemInfoPanel과 EquipButton이 함께 바뀌어야 한다. 각 UI가 서로 직접 연결되는 대신 InventoryMediator가 조정할 수 있다.

### 6. 간단한 Lua 예제

```lua
local UIMediator = {}

function UIMediator:itemSelected(item)
    print("아이템 정보 갱신:", item)
    print("장착 버튼 활성화")
end

local ItemList = { mediator = UIMediator }

function ItemList:select(item)
    print("선택:", item)
    self.mediator:itemSelected(item)
end

ItemList:select("Sword")
```

### 7. 장점

- 객체 간 직접 의존을 줄일 수 있다.
- 복잡한 통신 로직을 한곳에서 관리할 수 있다.
- 각 Component를 단순하게 만들 수 있다.

### 8. 단점

- Mediator에 역할이 너무 몰리면 거대한 객체가 될 수 있다.
- 모든 흐름을 Mediator가 담당하면 유지보수가 어려워질 수 있다.

### 9. 핵심 키워드

`중재자`, `중앙 통신`, `결합도 감소`, `Component`, `상호작용 관리`

### 10. 헷갈리기 쉬운 패턴

#### Mediator vs Observer

- **Mediator**: 여러 객체의 **상호작용 규칙을 중앙에서 조정**한다.
- **Observer**: 한 객체의 **변화를 여러 구독자에게 알린다**.
