# Iterator Pattern

> **카테고리:** Behavioral Patterns (행동 패턴)  
> **학습 순서:** 18/22

---

### 1. 한 줄 요약

**컬렉션 내부 구조를 직접 노출하지 않고 요소를 하나씩 순서대로 접근하게 하는 패턴이다.**

### 2. 사용하는 이유

Inventory가 배열인지 연결 리스트인지 몰라도 같은 방식으로 아이템을 순회하고 싶을 때 사용한다.

### 3. 핵심 구조

- **Collection / Aggregate**: 여러 요소를 보관
- **Iterator**: 현재 위치를 기억하고 다음 요소를 제공
- **Client**: Iterator를 이용해 요소를 순회

Lua의 `ipairs`, `pairs`도 반복을 추상화해 준다는 점에서 Iterator 개념을 이해하는 데 도움이 된다.

### 4. 동작 과정

1. Collection에서 Iterator를 얻는다.
2. Iterator가 현재 위치를 기억한다.
3. `next()`로 다음 요소를 하나씩 반환한다.
4. 끝까지 반복한다.

### 5. 게임 개발 예시

Inventory의 모든 아이템을 순서대로 확인하면서 화면에 표시하거나 특정 아이템을 찾을 수 있다.

### 6. 간단한 Lua 예제

```lua
local Inventory = {
    items = { "Sword", "Potion", "Key" }
}

function Inventory:createIterator()
    local index = 0

    return function()
        index = index + 1
        return self.items[index]
    end
end

local nextItem = Inventory:createIterator()

while true do
    local item = nextItem()
    if item == nil then break end
    print(item)
end
```

### 7. 장점

- Collection 내부 구조를 숨길 수 있다.
- 순회 로직을 별도로 관리할 수 있다.
- 여러 방식의 순회 방법을 만들 수 있다.

### 8. 단점

- 단순한 배열 순회에는 불필요하게 느껴질 수 있다.
- Iterator 상태를 관리해야 한다.

### 9. 핵심 키워드

`순회`, `컬렉션`, `next`, `내부 구조 숨김`, `반복`

### 10. 헷갈리기 쉬운 패턴

Visitor도 컬렉션의 여러 객체를 방문할 수 있지만 목적이 다르다.

- **Iterator**: 요소를 **어떤 순서로 접근할지**.
- **Visitor**: 여러 종류의 객체에 **어떤 작업을 수행할지**.
