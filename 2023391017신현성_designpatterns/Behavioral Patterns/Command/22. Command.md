# Command Pattern

> **카테고리:** Behavioral Patterns (행동 패턴)  
> **학습 순서:** 22/22

---

### 1. 한 줄 요약

**실행할 요청이나 명령 자체를 객체로 만들어 저장, 전달, 취소, 재실행할 수 있게 하는 패턴이다.**

### 2. 사용하는 이유

버튼을 눌렀을 때 실행할 기능과 버튼 자체를 분리하고 싶거나, 입력 기록, Undo, Replay, 명령 큐 같은 기능이 필요할 때 사용한다.

### 3. 핵심 구조

- **Command**: 실행 기능의 공통 규칙
- **Concrete Command**: 실제 요청을 객체로 표현
- **Receiver**: 진짜 작업을 수행하는 대상
- **Invoker**: Command를 실행시키는 객체

### 4. 동작 과정

1. 실제 작업을 수행할 Receiver를 준비한다.
2. Receiver의 작업을 호출하는 Command를 만든다.
3. Invoker에 Command를 등록한다.
4. Invoker가 Command의 `execute()`를 호출한다.
5. 필요하면 Command를 저장하거나 Undo/Replay에 사용한다.

### 5. 게임 개발 예시

키보드 W 입력에 MoveUpCommand를 연결하고, 마우스 클릭에 AttackCommand를 연결할 수 있다. 입력 기록을 저장하면 리플레이나 Undo에도 활용할 수 있다.

### 6. 간단한 Lua 예제

```lua
local Player = {}
function Player:attack()
    print("Player 공격")
end

local AttackCommand = { receiver = Player }
function AttackCommand:execute()
    self.receiver:attack()
end

local Input = {}
function Input:setCommand(command)
    self.command = command
end

function Input:pressButton()
    self.command:execute()
end

Input:setCommand(AttackCommand)
Input:pressButton()
```

### 7. 장점

- 명령을 실행하는 객체와 실제 기능을 분리할 수 있다.
- 명령 큐, 로그, Undo, Replay 기능을 만들기 좋다.
- 같은 Invoker에 다른 Command를 자유롭게 연결할 수 있다.

### 8. 단점

- 간단한 요청도 Command 객체로 만들면 코드가 늘어난다.
- 명령 종류가 많으면 Command 수도 많아진다.

### 9. 핵심 키워드

`명령 객체`, `execute`, `Invoker`, `Receiver`, `Undo/Replay`

### 10. 헷갈리기 쉬운 패턴

#### Command vs Strategy

- **Command**: “무엇을 실행하라”라는 **요청 자체를 객체화**한다.
- **Strategy**: 같은 목적을 이루는 **알고리즘/행동 방식을 교체**한다.

#### Command vs Chain of Responsibility

- **Command**: 요청을 객체로 포장해서 저장하거나 전달한다.
- **Chain of Responsibility**: 들어온 요청을 여러 Handler 중 누가 처리할지 전달한다.
