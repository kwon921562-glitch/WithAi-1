# Chain of Responsibility Pattern

> **카테고리:** Behavioral Patterns (행동 패턴)  
> **학습 순서:** 21/22

---

### 1. 한 줄 요약

**요청을 여러 처리자에게 순서대로 넘기면서, 처리 가능한 객체가 요청을 처리하게 하는 패턴이다.**

### 2. 사용하는 이유

요청을 누가 처리해야 할지 처음부터 확정하기 어렵거나, 여러 처리 단계를 차례로 거쳐야 할 때 처리자들을 체인으로 연결한다.

### 3. 핵심 구조

- **Handler**: 요청 처리 기능과 다음 Handler 참조를 가짐
- **Concrete Handler**: 자신이 처리할 수 있는 요청인지 확인
- **Client**: 체인의 첫 Handler에게 요청 전달

### 4. 동작 과정

1. 여러 Handler를 순서대로 연결한다.
2. 요청을 첫 Handler에게 보낸다.
3. 현재 Handler가 처리할 수 있으면 처리한다.
4. 처리하지 못하면 다음 Handler로 넘긴다.
5. 필요한 경우 여러 Handler가 연속으로 처리하게 만들 수도 있다.

### 5. 게임 개발 예시

입력 처리에서 UI → Player → World 순서로 이벤트를 전달할 수 있다. UI가 클릭을 처리했다면 뒤로 넘기지 않고, 아니면 Player나 World가 처리한다.

### 6. 간단한 Lua 예제

```lua
local function uiHandler(event)
    if event == "menu_click" then
        print("UI가 처리")
        return true
    end
    return false
end

local function playerHandler(event)
    if event == "attack" then
        print("Player가 처리")
        return true
    end
    return false
end

local handlers = { uiHandler, playerHandler }

local function handle(event)
    for _, handler in ipairs(handlers) do
        if handler(event) then
            return -- 처리되면 체인 종료
        end
    end

    print("처리할 수 없는 요청")
end

handle("attack")
```

### 7. 장점

- 요청을 보내는 쪽이 실제 처리자를 몰라도 된다.
- 처리 순서를 쉽게 변경하거나 Handler를 추가할 수 있다.
- 여러 조건문을 Handler로 분리할 수 있다.

### 8. 단점

- 아무도 요청을 처리하지 않을 수 있다.
- 요청이 체인을 따라가므로 흐름 추적이 어려울 수 있다.
- 체인이 너무 길면 처리 비용이 늘 수 있다.

### 9. 핵심 키워드

`요청 전달`, `처리자 체인`, `순서`, `다음 Handler`, `책임 전달`

### 10. 헷갈리기 쉬운 패턴

#### Chain of Responsibility vs Command

- **Chain of Responsibility**: 요청을 **누가 처리할지 체인을 따라 찾는다**.
- **Command**: 요청 자체를 **하나의 객체로 포장한다**.
