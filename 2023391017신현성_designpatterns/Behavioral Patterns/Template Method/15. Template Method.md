# Template Method Pattern

> **카테고리:** Behavioral Patterns (행동 패턴)  
> **학습 순서:** 15/22

---

### 1. 한 줄 요약

**전체 작업 순서는 부모가 정해 두고, 일부 단계만 하위 구현에서 바꾸게 하는 패턴이다.**

### 2. 사용하는 이유

여러 객체가 대부분 같은 순서로 동작하지만 중간 몇 단계만 다를 때 전체 코드를 복사하지 않고 공통 흐름을 재사용할 수 있다.

### 3. 핵심 구조

- **Template Method**: 전체 실행 순서를 정의하는 메서드
- **Primitive Operation / Step**: 하위 구현이 바꿀 수 있는 각 단계
- **Concrete Class**: 필요한 Step을 구체적으로 구현

Lua에서는 상속 대신 테이블과 함수 참조를 이용해 비슷한 구조를 만들 수 있다.

### 4. 동작 과정

1. 공통 실행 순서를 하나의 함수로 정의한다.
2. 실행 순서 중 바뀌는 부분을 별도 함수로 둔다.
3. 각 구현이 그 일부 함수만 다르게 제공한다.
4. 전체 순서는 동일하게 유지된다.

### 5. 게임 개발 예시

Enemy AI의 기본 턴을 `탐색 → 이동 → 공격 → 턴 종료`로 고정하고, Boss와 NormalEnemy가 이동이나 공격 방법만 다르게 구현할 수 있다.

### 6. 간단한 Lua 예제

```lua
local function takeTurn(enemy)
    print("플레이어 탐색")
    enemy:move()   -- 종류마다 다르게 구현
    enemy:attack() -- 종류마다 다르게 구현
    print("턴 종료")
end

local Boss = {}
function Boss:move()
    print("보스가 크게 이동")
end
function Boss:attack()
    print("보스 강공격")
end

takeTurn(Boss)
```

### 7. 장점

- 중복 코드를 줄일 수 있다.
- 전체 알고리즘 순서를 일관되게 유지할 수 있다.
- 일부 단계만 쉽게 변경할 수 있다.

### 8. 단점

- 고정된 실행 순서 때문에 유연성이 떨어질 수 있다.
- 상속 기반 구현에서는 부모와 자식의 결합이 강해질 수 있다.

### 9. 핵심 키워드

`작업 순서`, `뼈대`, `일부 단계 변경`, `공통 흐름`, `재사용`

### 10. 헷갈리기 쉬운 패턴

#### Template Method vs Strategy

- **Template Method**: 알고리즘의 **전체 순서를 고정**하고 일부 단계만 바꾼다.
- **Strategy**: 알고리즘이나 행동 **전체를 다른 객체로 교체**한다.
