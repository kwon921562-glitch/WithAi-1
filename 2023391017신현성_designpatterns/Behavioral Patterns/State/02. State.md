# State Pattern

> **카테고리:** Behavioral Patterns (행동 패턴)  
> **학습 순서:** 2/22

---

### 1. 한 줄 요약

**객체의 현재 상태를 별도 객체로 만들고, 상태가 바뀌면 행동도 함께 바뀌게 하는 패턴이다.**

### 2. 사용하는 이유

캐릭터가 Idle, Run, Jump, Attack, Dead 같은 여러 상태를 가질 때 모든 처리를 조건문으로 작성하면 매우 복잡해진다. 상태별 행동을 분리하면 각 상태의 코드가 명확해진다.

### 3. 핵심 구조

- **Context**: 현재 상태를 가지고 있는 객체. 예: Player
- **State**: 상태들이 따라야 하는 공통 규칙
- **Concrete State**: IdleState, RunState, AttackState 등 실제 상태

### 4. 동작 과정

1. Context가 현재 State를 하나 가진다.
2. 행동 요청이 오면 현재 State에게 처리를 맡긴다.
3. 특정 조건이 생기면 State를 다른 State로 바꾼다.
4. 이후 행동은 새 State의 방식으로 처리된다.

### 5. 게임 개발 예시

Enemy가 Patrol 상태에서는 순찰하고, Chase 상태에서는 플레이어를 추적하고, Attack 상태에서는 공격하도록 만들 수 있다.

### 6. 간단한 Lua 예제

```lua
local IdleState = {}
function IdleState:update(player)
    print("대기 중")
end

local RunState = {}
function RunState:update(player)
    print("달리는 중")
end

local Player = {}
function Player:new()
    local obj = { state = IdleState }
    setmetatable(obj, self)
    self.__index = self
    return obj
end

function Player:update()
    self.state:update(self)
end

local player = Player:new()
player:update()

player.state = RunState -- 상태 변경
player:update()
```

### 7. 장점

- 상태별 코드를 분리할 수 있다.
- 복잡한 조건문을 줄일 수 있다.
- 새로운 상태를 추가하기 쉽다.
- 상태 전환 구조가 명확해진다.

### 8. 단점

- 상태가 많으면 클래스/테이블 수도 많아진다.
- 단순한 상태 몇 개만 있다면 과한 구조가 될 수 있다.
- 상태 전환 관계가 복잡하면 관리가 필요하다.

### 9. 핵심 키워드

`현재 상태`, `상태 전환`, `FSM`, `행동 변화`, `조건문 감소`

### 10. 헷갈리기 쉬운 패턴

#### State vs Strategy

- **State**: 현재 상태 자체가 행동을 결정한다.
- **Strategy**: 같은 목적을 수행하는 여러 방법 중 하나를 선택한다.

퀴즈에서 `Idle`, `Run`, `Attack`, `Dead` 같은 말이 나오면 State를 먼저 의심하면 좋다.
