# Strategy Pattern

> **카테고리:** Behavioral Patterns (행동 패턴)  
> **학습 순서:** 1/22

---

### 1. 한 줄 요약

**여러 행동이나 알고리즘을 각각 분리해 두고, 필요할 때 원하는 행동으로 교체해서 사용하는 패턴이다.**

### 2. 사용하는 이유

하나의 객체가 상황에 따라 여러 방식으로 같은 일을 해야 할 때 `if`, `elseif`가 계속 늘어나면 코드가 복잡해진다. Strategy는 각 행동을 별도 객체로 분리해서 새로운 행동을 추가하거나 기존 행동을 교체하기 쉽게 만든다.

### 3. 핵심 구조

- **Context**: 실제로 Strategy를 사용하는 객체. 예: Player
- **Strategy**: 행동의 공통 규칙. 예: 공격 기능
- **Concrete Strategy**: 실제 행동. 예: SwordAttack, BowAttack, MagicAttack

### 4. 동작 과정

1. 사용할 행동 객체를 만든다.
2. Context가 그 행동 객체를 가지고 있는다.
3. Context가 직접 행동하지 않고 Strategy에게 일을 맡긴다.
4. 필요하면 Strategy만 다른 객체로 바꾼다.

### 5. 게임 개발 예시

플레이어가 검, 활, 마법 중 하나로 공격할 수 있다고 하자. Player에 세 공격 코드를 전부 넣는 대신 각 공격을 별도의 Strategy로 만들면, 무기가 바뀔 때 공격 Strategy만 교체할 수 있다.

### 6. 간단한 Lua 예제

```lua
-- 검 공격 전략
local SwordAttack = {}
function SwordAttack:attack()
    print("검으로 공격")
end

-- 활 공격 전략
local BowAttack = {}
function BowAttack:attack()
    print("활로 공격")
end

local Player = {}
function Player:new(strategy)
    local obj = { strategy = strategy }
    setmetatable(obj, self)
    self.__index = self
    return obj
end

function Player:attack()
    self.strategy:attack() -- 실제 공격은 Strategy에게 맡김
end

local player = Player:new(SwordAttack)
player:attack()

player.strategy = BowAttack -- 전략 교체
player:attack()
```

### 7. 장점

- 행동을 실행 중에 쉽게 교체할 수 있다.
- 큰 조건문을 줄일 수 있다.
- 새로운 행동을 추가하기 쉽다.
- 행동 코드와 사용하는 객체의 코드를 분리할 수 있다.

### 8. 단점

- 행동 종류가 적으면 오히려 구조가 복잡해질 수 있다.
- Strategy 객체가 많아질 수 있다.
- Context가 어떤 Strategy를 선택해야 하는지 알아야 할 수 있다.

### 9. 핵심 키워드

`알고리즘 교체`, `행동 분리`, `전략 객체`, `런타임 변경`, `위임`

### 10. 헷갈리기 쉬운 패턴

#### Strategy vs State

둘 다 비슷한 구조로 행동을 다른 객체에 맡긴다.

- **Strategy**: 사용자가 어떤 행동 방식을 사용할지 선택하거나 교체한다.
- **State**: 객체의 현재 상태가 바뀌면서 행동도 자연스럽게 바뀐다.

> 검 공격 ↔ 활 공격을 선택한다 → **Strategy**  
> Idle → Run → Attack 상태에 따라 행동이 달라진다 → **State**
