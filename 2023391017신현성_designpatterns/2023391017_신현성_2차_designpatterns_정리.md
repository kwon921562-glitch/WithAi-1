# 생성 패턴 (Creational Patterns)

생성 패턴은 **객체를 어떻게 만들지**에 관한 패턴입니다.  
객체를 만드는 과정이 복잡하거나, 어떤 객체를 만들지 자주 바뀌는 경우에 사용합니다.

## Abstract Factory

서로 관련된 객체들을 **한 세트로 묶어서 생성**하는 패턴입니다.  
예를 들어 불 지역용 적, 무기, 아이템을 한 번에 같은 테마로 만들고 싶을 때 사용합니다.

- **판단 기준:** 관련된 객체 여러 개를 한 묶음으로 만들어야 할 때
- **핵심 키워드:** 제품군 / 세트 생성

## Builder

복잡한 객체를 **여러 단계로 나누어 하나씩 조립**하는 패턴입니다.  
설정할 값이나 선택 옵션이 많고, 같은 객체를 여러 형태로 만들고 싶을 때 사용합니다.

- **판단 기준:** 옵션이 많고 단계별로 객체를 만들고 싶을 때
- **핵심 키워드:** 단계별 생성 / 조립

## Factory Method

어떤 객체를 만들지는 직접 결정하지 않고 **생성하는 부분을 따로 분리**하는 패턴입니다.  
새로운 객체 종류가 추가되어도 사용하는 쪽의 코드를 크게 바꾸고 싶지 않을 때 사용합니다.

- **판단 기준:** 객체 생성 부분을 사용 코드와 분리하고 싶을 때
- **핵심 키워드:** 생성 책임 분리

## Prototype

이미 만들어진 객체를 **복사해서 새로운 객체를 만드는** 패턴입니다.  
비슷한 객체를 많이 만들거나, 처음부터 새로 만드는 비용이 큰 경우에 사용합니다.

- **판단 기준:** 기존 객체를 복제해서 빠르게 만들고 싶을 때
- **핵심 키워드:** 복제

## Singleton

특정 객체를 **프로그램 전체에서 하나만 존재하도록** 만드는 패턴입니다.  
GameManager처럼 어디서든 같은 하나의 객체를 사용해야 할 때 적합합니다.

- **판단 기준:** 반드시 하나만 존재해야 하는 객체일 때
- **핵심 키워드:** 하나만 존재

# 구조 패턴 (Structural Patterns)

구조 패턴은 **객체나 클래스를 어떻게 연결하고 조합할지**에 관한 패턴입니다.  
기존 코드를 크게 수정하지 않고 구조를 확장하거나, 객체 사이의 관계를 정리할 때 사용합니다.

## Adapter

서로 맞지 않는 인터페이스를 **중간에서 변환해 연결**해주는 패턴입니다.  
기존 코드나 외부 라이브러리를 수정하지 않고 현재 코드에 맞춰 사용하고 싶을 때 사용합니다.

- **판단 기준:** 서로 형식이 맞지 않는 두 기능을 연결해야 할 때
- **핵심 키워드:** 인터페이스 변환

## Bridge

기능과 실제 구현을 **서로 분리해서 각각 변경할 수 있게** 만드는 패턴입니다.  
기능 종류와 구현 종류가 둘 다 계속 늘어날 때 조합 폭발을 줄이는 데 도움이 됩니다.

- **판단 기준:** 기능과 구현을 따로 확장하고 싶을 때
- **핵심 키워드:** 추상화 / 구현 분리

## Composite

여러 객체를 **트리 구조로 묶고, 개별 객체와 묶음을 같은 방식으로 다루는** 패턴입니다.  
UI 계층이나 오브젝트 트리처럼 부분과 전체를 같은 방식으로 처리할 때 사용합니다.

- **판단 기준:** 객체가 계층 구조를 이루고 부분과 전체를 똑같이 다뤄야 할 때
- **핵심 키워드:** 트리 구조

## Decorator

기존 객체를 수정하지 않고 **겉에 기능을 덧붙이는** 패턴입니다.  
무기에 불 속성이나 독 속성을 추가하는 것처럼 기능을 자유롭게 조합하고 싶을 때 사용합니다.

- **판단 기준:** 기존 기능은 유지하면서 추가 기능만 붙이고 싶을 때
- **핵심 키워드:** 기능 추가

## Facade

복잡한 여러 기능을 **하나의 간단한 사용 방법으로 감싸는** 패턴입니다.  
여러 시스템을 하나하나 호출하지 않고 한 번에 쉽게 사용하고 싶을 때 적합합니다.

- **판단 기준:** 복잡한 시스템을 간단하게 사용하게 만들고 싶을 때
- **핵심 키워드:** 단순화

## Flyweight

많은 객체가 사용하는 공통 데이터를 **공유해서 메모리를 아끼는** 패턴입니다.  
나무, 총알, 타일처럼 같은 데이터를 가진 객체가 아주 많이 있을 때 사용합니다.

- **판단 기준:** 비슷한 객체가 너무 많아 메모리를 줄이고 싶을 때
- **핵심 키워드:** 공유 / 메모리 절약

## Proxy

실제 객체 대신 **대리 객체가 먼저 접근을 관리**하는 패턴입니다.  
권한 확인, 지연 로딩, 캐시처럼 실제 객체를 사용하기 전에 추가 처리가 필요할 때 사용합니다.

- **판단 기준:** 실제 객체에 바로 접근시키고 싶지 않을 때
- **핵심 키워드:** 대리 / 접근 제어

# 행동 패턴 (Behavioral Patterns)

행동 패턴은 **객체가 어떻게 행동하고 서로 협력할지**에 관한 패턴입니다.  
행동을 바꾸거나, 상태를 관리하거나, 객체 사이에 요청과 알림을 전달할 때 사용합니다.

## Chain of Responsibility

요청을 여러 처리자에게 **순서대로 넘기면서 처리할 수 있는 객체가 맡는** 패턴입니다.  
입력이나 이벤트를 여러 단계에서 검사하고 처리해야 할 때 사용합니다.

- **판단 기준:** 하나의 요청을 여러 객체가 순서대로 검사해야 할 때
- **핵심 키워드:** 요청 전달

## Command

요청이나 행동 자체를 **하나의 객체로 만들어 저장하고 실행**하는 패턴입니다.  
입력 설정, 실행 취소, 재실행, 리플레이처럼 행동을 기록하거나 나중에 실행할 때 사용합니다.

- **판단 기준:** 행동 자체를 저장하거나 되돌리고 싶을 때
- **핵심 키워드:** 명령 객체화

## Iterator

자료구조 내부를 직접 알지 않아도 **요소를 하나씩 순서대로 꺼내 보는** 패턴입니다.  
인벤토리나 리스트처럼 여러 데이터를 같은 방식으로 탐색할 때 사용합니다.

- **판단 기준:** 내부 구조를 몰라도 순서대로 데이터를 보고 싶을 때
- **핵심 키워드:** 순회

## Mediator

여러 객체가 서로 직접 연결되지 않고 **중간 관리자 하나를 통해 소통**하는 패턴입니다.  
UI 창처럼 객체끼리 연결이 너무 많아 복잡해졌을 때 사용합니다.

- **판단 기준:** 객체끼리 직접 연결이 너무 많아졌을 때
- **핵심 키워드:** 중재

## Memento

객체의 현재 상태를 **저장해 두었다가 나중에 다시 복원**하는 패턴입니다.  
체크포인트나 Undo처럼 이전 상태로 돌아가야 할 때 사용합니다.

- **판단 기준:** 예전 상태로 되돌릴 필요가 있을 때
- **핵심 키워드:** 저장 / 복원

## Observer

한 객체에 변화가 생기면 **등록된 다른 객체들에게 자동으로 알려주는** 패턴입니다.  
HP가 줄었을 때 UI, 사운드, 이펙트가 함께 반응해야 하는 경우에 사용할 수 있습니다.

- **판단 기준:** 하나의 변화에 여러 객체가 함께 반응해야 할 때
- **핵심 키워드:** 변화 알림

## State

객체의 현재 상태를 따로 나누고 **상태에 따라 행동이 달라지게** 만드는 패턴입니다.  
Idle, Run, Attack처럼 상태 종류가 많아지고 전환이 복잡해질 때 사용합니다.

- **판단 기준:** 현재 상태에 따라 같은 객체의 행동이 달라질 때
- **핵심 키워드:** 상태별 행동

## Strategy

여러 알고리즘이나 행동을 따로 분리하고 **필요할 때 교체해서 사용하는** 패턴입니다.  
검 공격, 활 공격처럼 같은 목적의 여러 행동 중 하나를 골라 사용할 때 적합합니다.

- **판단 기준:** 같은 목적의 행동을 상황에 따라 바꿔 쓰고 싶을 때
- **핵심 키워드:** 행동 교체

## Template Method

알고리즘의 **전체 순서는 고정하고 일부 단계만 바꾸는** 패턴입니다.  
공통적인 처리 순서는 같지만 특정 단계만 다르게 구현하고 싶을 때 사용합니다.

- **판단 기준:** 전체 흐름은 유지하고 일부 과정만 다르게 만들고 싶을 때
- **핵심 키워드:** 전체 흐름 고정

## Visitor

기존 객체 구조를 크게 바꾸지 않고 **새로운 기능을 외부에서 추가**하는 패턴입니다.  
여러 종류의 객체에 새로운 연산을 추가해야 할 때 사용합니다.

- **판단 기준:** 기존 구조는 유지하면서 새로운 기능만 계속 추가하고 싶을 때
- **핵심 키워드:** 새 연산 추가
