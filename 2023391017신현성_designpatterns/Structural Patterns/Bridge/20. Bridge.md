# Bridge Pattern

> **카테고리:** Structural Patterns (구조 패턴)  
> **학습 순서:** 20/22

---

### 1. 한 줄 요약

**한 클래스 안에서 함께 커지던 두 변화 축을 따로 분리해 서로 독립적으로 확장할 수 있게 하는 패턴이다.**

### 2. 사용하는 이유

예를 들어 Weapon 종류와 공격 효과 종류가 모두 늘어난다고 하자. 상속으로 모든 조합을 만들면 `FireSword`, `IceSword`, `FireBow`, `IceBow`처럼 클래스가 계속 늘어난다. Bridge는 Weapon과 Effect를 각각 분리하고 조합한다.

### 3. 핵심 구조

- **Abstraction**: 사용자에게 보이는 상위 기능
- **Implementation**: 실제 세부 구현 인터페이스
- **Refined Abstraction**: 확장된 상위 기능
- **Concrete Implementation**: 실제 구현체

### 4. 동작 과정

1. 크게 변화하는 두 영역을 찾는다.
2. 각각 별도의 구조로 분리한다.
3. Abstraction이 Implementation 객체를 보관한다.
4. 실행할 때 두 객체를 조합해서 사용한다.

### 5. 게임 개발 예시

Sword/Bow와 FireEffect/IceEffect를 따로 만든 뒤 `Sword + FireEffect`, `Bow + IceEffect`처럼 자유롭게 조합할 수 있다.

### 6. 간단한 Lua 예제

```lua
local FireEffect = {}
function FireEffect:apply()
    print("불 효과 적용")
end

local IceEffect = {}
function IceEffect:apply()
    print("얼음 효과 적용")
end

local Weapon = {}
function Weapon:new(name, effect)
    return setmetatable({ name = name, effect = effect }, { __index = self })
end

function Weapon:attack()
    print(self.name .. " 공격")
    self.effect:apply()
end

local sword = Weapon:new("Sword", FireEffect)
local bow = Weapon:new("Bow", IceEffect)

sword:attack()
bow:attack()
```

### 7. 장점

- 두 변화 축을 독립적으로 확장할 수 있다.
- 클래스 조합 폭발을 줄일 수 있다.
- 상속보다 조합을 활용하기 좋다.

### 8. 단점

- 작은 시스템에서는 구조가 복잡해 보일 수 있다.
- 처음 설계할 때 어떤 축을 분리해야 하는지 판단이 필요하다.

### 9. 핵심 키워드

`추상화-구현 분리`, `두 변화 축`, `독립 확장`, `조합`, `클래스 폭발 방지`

### 10. 헷갈리기 쉬운 패턴

#### Bridge vs Adapter

- **Bridge**: 처음부터 두 부분이 **독립적으로 확장**되도록 설계한다.
- **Adapter**: 이미 존재하는 **호환되지 않는 인터페이스를 연결**한다.

퀴즈에서 “서로 다른 두 종류가 조합되면서 각각 계속 확장된다”는 상황이면 Bridge를 생각하는 것이 좋다.
