# Proxy Pattern

> **카테고리:** Structural Patterns (구조 패턴)  
> **학습 순서:** 12/22

---

### 1. 한 줄 요약

**실제 객체 대신 앞에 대리 객체를 두어 접근을 제어하거나 필요한 작업을 대신 처리하는 패턴이다.**

### 2. 사용하는 이유

실제 객체 생성 비용이 크거나, 권한 검사·캐싱·지연 로딩 같은 처리가 필요할 때 Client가 실제 객체에 바로 접근하지 않도록 Proxy를 둔다.

### 3. 핵심 구조

- **Subject**: 실제 객체와 Proxy가 따르는 공통 기능
- **Real Subject**: 진짜 작업을 수행하는 객체
- **Proxy**: 접근 제어, 캐싱, 지연 생성 등을 담당

### 4. 동작 과정

1. Client가 Real Subject 대신 Proxy를 호출한다.
2. Proxy가 권한, 캐시, 생성 여부 등을 확인한다.
3. 필요하면 Real Subject를 호출한다.
4. 결과를 Client에게 반환한다.

### 5. 게임 개발 예시

고해상도 캐릭터 모델을 바로 로드하지 않고, 화면에 실제로 필요해졌을 때 Proxy가 모델을 로드하도록 만들 수 있다.

### 6. 간단한 Lua 예제

```lua
local RealTexture = {}
function RealTexture:load()
    print("큰 텍스처 실제 로딩")
end

local TextureProxy = { real = nil }

function TextureProxy:show()
    if self.real == nil then
        self.real = RealTexture
        self.real:load() -- 필요한 순간에만 로딩
    end

    print("텍스처 표시")
end

TextureProxy:show()
```

### 7. 장점

- 실제 객체 접근을 제어할 수 있다.
- 지연 로딩이나 캐싱을 구현하기 좋다.
- Client는 Proxy와 Real Object의 차이를 크게 신경 쓰지 않아도 된다.

### 8. 단점

- 호출 단계가 하나 늘어난다.
- Proxy 로직이 복잡해질 수 있다.
- 실제 작업이 언제 일어나는지 파악이 어려울 수 있다.

### 9. 핵심 키워드

`대리`, `접근 제어`, `지연 로딩`, `캐싱`, `Real Subject`

### 10. 헷갈리기 쉬운 패턴

#### Proxy vs Decorator

- **Proxy**: 접근을 관리하거나 대신 수행하는 것이 중심.
- **Decorator**: 원본에 새로운 기능을 덧붙이는 것이 중심.
