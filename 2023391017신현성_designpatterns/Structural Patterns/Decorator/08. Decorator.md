# Decorator Pattern

> **카테고리:** Structural Patterns (구조 패턴)  
> **학습 순서:** 8/22

---

### 1. 한 줄 요약

**기존 객체를 다른 객체로 감싸서 원본을 수정하지 않고 기능을 덧붙이는 패턴이다.**

### 2. 사용하는 이유

상속만으로 모든 기능 조합을 만들면 클래스 수가 폭발할 수 있다. Decorator를 사용하면 필요한 기능을 여러 겹 조합해서 붙일 수 있다.

### 3. 핵심 구조

- **Component**: 기본 기능의 공통 인터페이스
- **Concrete Component**: 원래 기능을 가진 객체
- **Decorator**: Component를 내부에 보관하면서 같은 인터페이스 제공
- **Concrete Decorator**: 추가 기능 구현

### 4. 동작 과정

1. 기본 객체를 만든다.
2. 추가 기능을 가진 Decorator가 기본 객체를 감싼다.
3. 호출이 Decorator를 거쳐 원래 객체로 전달된다.
4. 전달 전후에 추가 기능을 실행한다.

### 5. 게임 개발 예시

기본 Sword에 FireDecorator와 PoisonDecorator를 차례로 감싸서 불 속성 + 독 속성을 가진 무기를 만들 수 있다.

### 6. 간단한 Lua 예제

```lua
local Sword = {}
function Sword:attack()
    print("기본 검 공격")
end

local FireDecorator = {}
function FireDecorator:new(weapon)
    return setmetatable({ weapon = weapon }, { __index = self })
end
function FireDecorator:attack()
    self.weapon:attack()
    print("+ 불 속성 데미지")
end

local weapon = FireDecorator:new(Sword)
weapon:attack()
```

### 7. 장점

- 상속 없이 기능을 동적으로 추가할 수 있다.
- 여러 기능을 원하는 조합으로 겹쳐 사용할 수 있다.
- 원본 객체를 수정하지 않아도 된다.

### 8. 단점

- Decorator가 여러 겹이면 객체 구조를 추적하기 어렵다.
- 작은 객체 수가 많이 늘어날 수 있다.
- 특정 Decorator의 순서에 따라 결과가 달라질 수 있다.

### 9. 핵심 키워드

`감싸기`, `기능 추가`, `동적 확장`, `조합`, `Wrapper`

### 10. 헷갈리기 쉬운 패턴

#### Decorator vs Proxy

둘 다 원본 객체를 감싸고 같은 인터페이스를 제공할 수 있다.

- **Decorator**: 원본에 **새로운 기능을 추가**하는 것이 목적.
- **Proxy**: 원본에 대한 **접근을 제어하거나 대신 처리**하는 것이 목적.

#### Decorator vs Composite

Decorator는 보통 한 객체를 감싸고, Composite는 여러 자식 객체를 묶어 트리를 만든다.
