# Flyweight Pattern

> **카테고리:** Structural Patterns (구조 패턴)  
> **학습 순서:** 14/22

---

### 1. 한 줄 요약

**수많은 비슷한 객체가 공통 데이터를 공유하게 해서 메모리 사용량을 줄이는 패턴이다.**

### 2. 사용하는 이유

나무 10,000개나 총알 100,000개가 모두 같은 이미지, 모델, 기본 설정을 각각 복사해서 가진다면 메모리를 많이 사용한다. 공통 데이터는 공유하고 개별 데이터만 따로 가지면 효율적이다.

### 3. 핵심 구조

- **Flyweight**: 여러 객체가 공유하는 공통 데이터
- **Intrinsic State**: 공유 가능한 내부 상태
- **Extrinsic State**: 위치처럼 각 객체마다 다른 외부 상태
- **Flyweight Factory**: 공유 객체를 찾아주거나 생성

### 4. 동작 과정

1. 공유 가능한 데이터를 Flyweight로 만든다.
2. Factory가 같은 종류의 Flyweight가 이미 있는지 확인한다.
3. 있으면 기존 객체를 재사용한다.
4. 각 객체는 위치, HP 같은 개별 데이터만 따로 가진다.

### 5. 게임 개발 예시

숲의 나무 수천 개가 같은 TreeModel과 Texture를 공유하고 위치와 크기만 각각 다르게 저장할 수 있다.

### 6. 간단한 Lua 예제

```lua
local TreeTypeFactory = { types = {} }

function TreeTypeFactory:getType(name)
    if self.types[name] == nil then
        -- 무거운 공통 데이터는 한 번만 생성
        self.types[name] = {
            model = name .. "_model",
            texture = name .. "_texture"
        }
    end

    return self.types[name]
end

local tree1 = { x = 10, type = TreeTypeFactory:getType("oak") }
local tree2 = { x = 20, type = TreeTypeFactory:getType("oak") }

print(tree1.type == tree2.type) -- true: 공통 객체 공유
```

### 7. 장점

- 많은 객체가 있을 때 메모리를 크게 절약할 수 있다.
- 중복 데이터를 줄일 수 있다.

### 8. 단점

- 공유 데이터와 개별 데이터를 분리해야 해서 코드가 복잡해질 수 있다.
- 모든 객체에 적용할 만한 패턴은 아니다.
- 공유 객체의 상태를 잘못 변경하면 여러 객체에 동시에 영향을 줄 수 있다.

### 9. 핵심 키워드

`공유`, `메모리 절약`, `대량 객체`, `Intrinsic`, `재사용`

### 10. 헷갈리기 쉬운 패턴

Prototype은 객체를 복제해서 새 객체를 만들고, Flyweight는 반대로 **같은 데이터를 가능한 한 공유**하려고 한다.
