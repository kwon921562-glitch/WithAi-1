# Composite Pattern

> **카테고리:** Structural Patterns (구조 패턴)  
> **학습 순서:** 7/22

---

### 1. 한 줄 요약

**개별 객체와 객체들의 묶음을 같은 방식으로 다룰 수 있게 하는 트리 구조 패턴이다.**

### 2. 사용하는 이유

UI, 파일 시스템, 게임 오브젝트 계층처럼 작은 요소 안에 또 다른 요소가 들어가는 구조에서는 개별 객체와 그룹을 따로 처리하면 코드가 복잡해진다. Composite는 둘을 같은 인터페이스로 다루게 한다.

### 3. 핵심 구조

- **Component**: 개별 객체와 그룹이 공통으로 따르는 기능
- **Leaf**: 더 이상 자식을 가지지 않는 개별 객체
- **Composite**: 여러 Component를 자식으로 가지는 그룹 객체

### 4. 동작 과정

1. Leaf와 Composite가 같은 기능을 제공한다.
2. Composite는 자식 목록을 가진다.
3. Composite에 작업을 요청하면 자신 또는 자식들에게 작업을 전달한다.
4. Client는 대상이 Leaf인지 Composite인지 크게 신경 쓰지 않는다.

### 5. 게임 개발 예시

UI Panel 안에 Button과 Text가 있고, Panel 안에 또 다른 Panel이 들어갈 수 있다. 모든 UI 요소에 `draw()`를 호출하는 식으로 다룰 수 있다.

### 6. 간단한 Lua 예제

```lua
local Button = {}
function Button:new(name)
    return setmetatable({ name = name }, { __index = self })
end
function Button:draw()
    print("버튼 그리기:", self.name)
end

local Panel = {}
function Panel:new()
    return setmetatable({ children = {} }, { __index = self })
end
function Panel:add(child)
    table.insert(self.children, child)
end
function Panel:draw()
    for _, child in ipairs(self.children) do
        child:draw() -- Button이든 Panel이든 같은 방식
    end
end

local root = Panel:new()
root:add(Button:new("Start"))
root:add(Button:new("Exit"))
root:draw()
```

### 7. 장점

- 트리 구조를 자연스럽게 표현할 수 있다.
- 개별 객체와 그룹을 같은 코드로 처리할 수 있다.
- 계층 구조에 새로운 Component를 추가하기 쉽다.

### 8. 단점

- 모든 객체에 같은 인터페이스를 맞추기 어려운 경우가 있다.
- 특정 타입에만 가능한 동작까지 공통 인터페이스에 넣으면 어색해질 수 있다.

### 9. 핵심 키워드

`트리`, `부모-자식`, `Leaf`, `그룹`, `동일 인터페이스`

### 10. 헷갈리기 쉬운 패턴

#### Composite vs Decorator

둘 다 객체를 감싸거나 재귀적인 구조를 만들 수 있지만 목적이 다르다.

- **Composite**: 여러 객체를 **트리 형태로 묶어 하나처럼 다루기**.
- **Decorator**: 기존 객체를 감싸서 **기능을 추가하기**.
