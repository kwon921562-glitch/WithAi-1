# Adapter Pattern

> **카테고리:** Structural Patterns (구조 패턴)  
> **학습 순서:** 5/22

---

### 1. 한 줄 요약

**서로 인터페이스가 맞지 않는 두 객체 사이에 변환기를 넣어 함께 사용할 수 있게 하는 패턴이다.**

### 2. 사용하는 이유

기존 코드와 외부 라이브러리가 같은 기능을 제공하더라도 함수 이름이나 데이터 형식이 다르면 바로 연결할 수 없다. Adapter가 그 차이를 변환해 준다.

### 3. 핵심 구조

- **Client**: 기존 방식으로 기능을 사용하려는 코드
- **Target**: Client가 기대하는 인터페이스
- **Adaptee**: 실제로 사용해야 하는 기존/외부 객체
- **Adapter**: Target 요청을 Adaptee가 이해하는 형태로 변환

### 4. 동작 과정

1. Client가 자신이 알고 있는 방식으로 Adapter를 호출한다.
2. Adapter가 요청을 외부 객체 형식으로 바꾼다.
3. Adaptee가 실제 작업을 수행한다.
4. 필요하면 결과도 다시 변환한다.

### 5. 게임 개발 예시

게임 내부에서는 `playSound()`를 사용하는데 외부 오디오 라이브러리는 `startAudio()`만 제공한다면 Adapter가 두 인터페이스를 연결할 수 있다.

### 6. 간단한 Lua 예제

```lua
-- 외부 라이브러리라고 가정
local OldAudio = {}
function OldAudio:startAudio(name)
    print("외부 오디오 재생:", name)
end

-- 우리 게임이 원하는 인터페이스
local AudioAdapter = { oldAudio = OldAudio }

function AudioAdapter:playSound(name)
    -- 이름이 다른 함수를 변환해서 호출
    self.oldAudio:startAudio(name)
end

AudioAdapter:playSound("attack.wav")
```

### 7. 장점

- 기존 코드를 수정하지 않고 호환시킬 수 있다.
- 외부 라이브러리 변경 영향을 줄일 수 있다.
- 변환 책임을 한곳에 모을 수 있다.

### 8. 단점

- Adapter 계층이 추가되어 구조가 늘어난다.
- 인터페이스 차이가 매우 크면 Adapter도 복잡해질 수 있다.

### 9. 핵심 키워드

`호환`, `변환`, `인터페이스`, `외부 라이브러리`, `연결`

### 10. 헷갈리기 쉬운 패턴

#### Adapter vs Facade

- **Adapter**: 기존 인터페이스를 **다른 인터페이스로 변환**한다.
- **Facade**: 복잡한 여러 기능을 **간단한 하나의 창구로 제공**한다.

#### Adapter vs Bridge

- **Adapter**: 이미 만들어진 서로 안 맞는 구조를 나중에 연결하는 경우가 많다.
- **Bridge**: 처음부터 추상화와 구현이 독립적으로 확장되도록 분리하는 설계다.
