# Facade Pattern

> **카테고리:** Structural Patterns (구조 패턴)  
> **학습 순서:** 6/22

---

### 1. 한 줄 요약

**복잡한 여러 시스템 앞에 간단한 대표 인터페이스 하나를 제공하는 패턴이다.**

### 2. 사용하는 이유

게임 시작 하나를 위해 Audio, UI, Save, Scene, Player 같은 여러 시스템을 직접 호출해야 하면 사용 코드가 너무 복잡해진다. Facade는 복잡한 내부 호출을 한곳에 감춘다.

### 3. 핵심 구조

- **Facade**: 외부에 단순한 기능을 제공하는 대표 객체
- **Subsystem**: 실제 일을 처리하는 여러 내부 시스템
- **Client**: Facade만 호출하는 외부 코드

### 4. 동작 과정

1. Client가 Facade의 간단한 기능을 호출한다.
2. Facade가 필요한 여러 Subsystem을 순서대로 호출한다.
3. Client는 내부 시스템의 복잡한 관계를 몰라도 된다.

### 5. 게임 개발 예시

`GameFacade:startGame()` 하나를 호출하면 Save를 불러오고, Scene을 로드하고, BGM을 재생하고, UI를 켜도록 만들 수 있다.

### 6. 간단한 Lua 예제

```lua
local Audio = {}
function Audio:playBGM() print("BGM 시작") end

local Scene = {}
function Scene:load() print("게임 씬 로드") end

local UI = {}
function UI:show() print("UI 표시") end

local GameFacade = {}
function GameFacade:startGame()
    Scene:load()
    Audio:playBGM()
    UI:show()
end

GameFacade:startGame()
```

### 7. 장점

- 복잡한 시스템 사용법을 단순하게 만든다.
- Client가 Subsystem에 강하게 의존하지 않게 할 수 있다.
- 자주 쓰는 복잡한 절차를 한 메서드로 묶을 수 있다.

### 8. 단점

- Facade에 기능을 너무 많이 몰아넣으면 거대한 객체가 될 수 있다.
- 내부의 세밀한 기능을 사용하려면 결국 Subsystem에 접근해야 할 수 있다.

### 9. 핵심 키워드

`단순화`, `대표 창구`, `Subsystem`, `복잡성 감추기`, `통합 인터페이스`

### 10. 헷갈리기 쉬운 패턴

#### Facade vs Adapter

Facade는 인터페이스를 **쉽게 단순화**하는 것이 핵심이고, Adapter는 서로 **호환되지 않는 인터페이스를 맞춰 주는 것**이 핵심이다.
