# Builder Pattern

> **카테고리:** Creational Patterns (생성 패턴)  
> **학습 순서:** 17/22

---

### 1. 한 줄 요약

**복잡한 객체를 여러 단계로 나누어 차근차근 만들어 가는 패턴이다.**

### 2. 사용하는 이유

생성자에 매개변수가 너무 많거나, 객체를 만드는 과정이 여러 단계일 때 Builder를 사용하면 생성 과정을 읽기 쉽게 만들 수 있다.

### 3. 핵심 구조

- **Builder**: 객체를 만드는 단계들을 제공
- **Concrete Builder**: 실제 생성 방법을 구현
- **Product**: 최종 완성 객체
- **Director(선택)**: 정해진 순서로 Builder를 호출

### 4. 동작 과정

1. Builder를 준비한다.
2. 필요한 속성을 단계별로 설정한다.
3. 선택 가능한 기능을 추가한다.
4. 마지막에 완성된 Product를 반환한다.

### 5. 게임 개발 예시

CharacterBuilder로 이름, HP, Weapon, Skill을 단계별로 설정해 여러 종류의 캐릭터를 만들 수 있다.

### 6. 간단한 Lua 예제

```lua
local CharacterBuilder = {}
function CharacterBuilder:new()
    return setmetatable({ character = {} }, { __index = self })
end

function CharacterBuilder:setName(name)
    self.character.name = name
    return self
end

function CharacterBuilder:setHP(hp)
    self.character.hp = hp
    return self
end

function CharacterBuilder:setWeapon(weapon)
    self.character.weapon = weapon
    return self
end

function CharacterBuilder:build()
    return self.character
end

local player = CharacterBuilder:new()
    :setName("Hero")
    :setHP(100)
    :setWeapon("Sword")
    :build()

print(player.name, player.hp, player.weapon)
```

### 7. 장점

- 복잡한 생성 과정을 읽기 쉽게 만들 수 있다.
- 필요한 옵션만 선택해서 객체를 만들기 쉽다.
- 생성 과정과 최종 객체를 분리할 수 있다.

### 8. 단점

- 단순한 객체에는 불필요하게 복잡하다.
- Builder 코드가 추가로 필요하다.

### 9. 핵심 키워드

`단계별 생성`, `복잡한 객체`, `옵션`, `Product`, `Build`

### 10. 헷갈리기 쉬운 패턴

Factory 계열은 **어떤 객체를 만들지**가 더 중요하고, Builder는 **한 복잡한 객체를 어떤 단계로 조립할지**가 더 중요하다.
