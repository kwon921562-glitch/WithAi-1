# Prototype Pattern

> **카테고리:** Creational Patterns (생성 패턴)  
> **학습 순서:** 10/22

---

### 1. 한 줄 요약

**새 객체를 처음부터 만들지 않고 기존 객체를 복제해서 생성하는 패턴이다.**

### 2. 사용하는 이유

객체 생성 과정이 복잡하거나 비용이 클 때 이미 설정이 끝난 객체를 복제하면 쉽게 비슷한 객체를 만들 수 있다.

### 3. 핵심 구조

- **Prototype**: 복제 기능을 제공하는 객체
- **Clone**: 기존 객체의 데이터를 복사하여 새 객체를 만드는 기능

### 4. 동작 과정

1. 기본 설정이 완료된 Prototype 객체를 준비한다.
2. 새 객체가 필요할 때 Prototype을 복제한다.
3. 필요한 값만 조금 수정한다.
4. 복제된 객체를 독립적으로 사용한다.

### 5. 게임 개발 예시

기본 Slime의 HP, Speed, Damage 설정을 복제한 뒤 색상이나 HP만 바꿔 RedSlime, BlueSlime을 만들 수 있다.

### 6. 간단한 Lua 예제

```lua
local function clone(original)
    local copy = {}

    for key, value in pairs(original) do
        copy[key] = value
    end

    return copy
end

local slime = {
    hp = 100,
    speed = 3,
    damage = 10
}

local redSlime = clone(slime)
redSlime.hp = 150

print(slime.hp)     -- 100
print(redSlime.hp)  -- 150
```

### 7. 장점

- 복잡한 생성 절차를 줄일 수 있다.
- 비슷한 객체를 빠르게 만들 수 있다.
- 구체적인 클래스에 대한 의존을 줄일 수 있다.

### 8. 단점

- 깊은 복사가 필요한 객체는 구현이 까다롭다.
- 참조 타입 데이터를 잘못 복사하면 원본과 데이터를 공유할 수 있다.

### 9. 핵심 키워드

`복제`, `Clone`, `기존 객체`, `빠른 생성`, `깊은 복사`

### 10. 헷갈리기 쉬운 패턴

#### Prototype vs Factory Method

- **Prototype**: 기존 객체를 **복사**해서 만든다.
- **Factory Method**: 생성 로직을 통해 **새 객체의 종류를 결정**한다.
