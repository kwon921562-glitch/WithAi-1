# Abstract Factory Pattern

> **카테고리:** Creational Patterns (생성 패턴)  
> **학습 순서:** 13/22

---

### 1. 한 줄 요약

**서로 관련된 여러 종류의 객체를 같은 테마나 규칙에 맞는 한 세트로 생성하는 패턴이다.**

### 2. 사용하는 이유

여러 객체가 서로 맞는 조합으로 생성되어야 할 때 개별 객체를 직접 만들면 잘못된 조합이 생길 수 있다. Abstract Factory는 한 Factory가 같은 계열의 Product들을 만들어 준다.

### 3. 핵심 구조

- **Abstract Factory**: 여러 Product를 만드는 공통 생성 규칙
- **Concrete Factory**: 특정 테마의 Product들을 생성
- **Abstract Product**: Product 종류별 공통 역할
- **Concrete Product**: 실제 생성 객체

### 4. 동작 과정

1. 사용할 테마의 Factory를 고른다.
2. Factory에게 필요한 객체들을 요청한다.
3. Factory가 같은 계열의 Product들을 반환한다.
4. Client는 Product의 구체적인 클래스를 직접 몰라도 된다.

### 5. 게임 개발 예시

FireFactory는 FireEnemy와 FireWeapon을 만들고, IceFactory는 IceEnemy와 IceWeapon을 만들도록 할 수 있다.

### 6. 간단한 Lua 예제

```lua
local FireFactory = {}
function FireFactory:createEnemy()
    return { name = "Fire Enemy" }
end
function FireFactory:createWeapon()
    return { name = "Fire Sword" }
end

local IceFactory = {}
function IceFactory:createEnemy()
    return { name = "Ice Enemy" }
end
function IceFactory:createWeapon()
    return { name = "Ice Sword" }
end

local factory = FireFactory
local enemy = factory:createEnemy()
local weapon = factory:createWeapon()

print(enemy.name, weapon.name)
```

### 7. 장점

- 서로 어울리는 객체 세트를 보장하기 쉽다.
- 구체적인 클래스에 대한 의존을 줄인다.
- 테마나 플랫폼 전체를 교체하기 쉽다.

### 8. 단점

- 새로운 Product 종류를 추가하면 모든 Factory를 수정해야 할 수 있다.
- 구조와 객체 수가 늘어난다.

### 9. 핵심 키워드

`객체 가족`, `세트 생성`, `테마`, `Factory`, `일관된 조합`

### 10. 헷갈리기 쉬운 패턴

#### Abstract Factory vs Factory Method

- **Factory Method**: 특정 Product를 어떻게 만들지 결정하는 데 초점.
- **Abstract Factory**: 관련된 여러 Product를 **한 세트**로 만드는 데 초점.
