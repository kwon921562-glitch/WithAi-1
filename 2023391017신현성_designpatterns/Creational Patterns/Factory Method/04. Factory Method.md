# Factory Method Pattern

> **카테고리:** Creational Patterns (생성 패턴)  
> **학습 순서:** 4/22

---

### 1. 한 줄 요약

**객체 생성 방법의 틀은 정해 두고, 실제로 어떤 객체를 만들지는 하위 구현이 결정하도록 하는 패턴이다.**

### 2. 사용하는 이유

객체를 사용하는 코드가 특정 클래스의 생성 방법에 직접 의존하면 새로운 종류를 추가할 때 코드 수정이 커진다. 생성 책임을 Factory Method로 분리하면 어떤 객체를 만들지 쉽게 바꿀 수 있다.

### 3. 핵심 구조

- **Product**: 생성될 객체의 공통 역할
- **Concrete Product**: 실제 생성되는 객체
- **Creator**: 객체를 사용하는 기본 흐름을 가진 쪽
- **Factory Method**: 실제 객체 생성을 담당하는 메서드

### 4. 동작 과정

1. Creator가 객체가 필요해진다.
2. 직접 생성하지 않고 Factory Method를 호출한다.
3. 구현에 따라 다른 Product가 만들어진다.
4. Creator는 구체적인 종류를 몰라도 공통 방식으로 사용한다.

### 5. 게임 개발 예시

스테이지 종류에 따라 NormalEnemy나 BossEnemy를 생성하는 Spawner를 만들 수 있다.

### 6. 간단한 Lua 예제

```lua
local NormalEnemy = {}
function NormalEnemy:new()
    return { name = "Normal Enemy" }
end

local BossEnemy = {}
function BossEnemy:new()
    return { name = "Boss Enemy" }
end

-- 어떤 적을 만들지 결정하는 Factory Method
local function createEnemy(enemyType)
    if enemyType == "boss" then
        return BossEnemy:new()
    end

    return NormalEnemy:new()
end

local enemy = createEnemy("boss")
print(enemy.name)
```

### 7. 장점

- 객체 생성 코드와 사용 코드를 분리할 수 있다.
- 새로운 Product를 추가하기 쉽다.
- 구체 클래스에 대한 직접 의존을 줄일 수 있다.

### 8. 단점

- 생성 종류가 적다면 구조가 불필요하게 복잡할 수 있다.
- 전형적인 객체지향 구현에서는 하위 클래스가 늘어날 수 있다.

### 9. 핵심 키워드

`객체 생성`, `생성 책임 분리`, `Product`, `Creator`, `하위 구현 결정`

### 10. 헷갈리기 쉬운 패턴

#### Factory Method vs Abstract Factory

- **Factory Method**: 보통 **한 종류의 Product 계층**에서 무엇을 만들지 정한다.
- **Abstract Factory**: 서로 관련된 **여러 종류의 객체를 한 세트**로 만든다.

> Enemy 하나의 종류를 선택해서 생성 → Factory Method  
> FireEnemy + FireWeapon + FireEffect처럼 같은 테마의 세트를 생성 → Abstract Factory
