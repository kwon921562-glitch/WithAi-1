# Singleton Pattern

> **카테고리:** Creational Patterns (생성 패턴)  
> **학습 순서:** 16/22

---

### 1. 한 줄 요약

**특정 객체가 프로그램 전체에서 하나만 존재하도록 하고 어디서든 그 하나에 접근하게 하는 패턴이다.**

### 2. 사용하는 이유

GameManager나 AudioManager처럼 여러 개 생기면 안 되고 하나의 공통 상태를 관리해야 하는 객체가 있을 때 사용한다.

### 3. 핵심 구조

- 외부에서 마음대로 새 객체를 만들지 못하게 한다.
- 내부에서 하나의 Instance를 보관한다.
- 모든 코드가 같은 Instance를 사용한다.

Lua의 `require` 모듈은 같은 모듈 값을 재사용하므로 Singleton처럼 활용하기도 한다.

### 4. 동작 과정

1. Singleton 객체를 한 번 만든다.
2. 공용 접근 지점을 제공한다.
3. 이후 요청은 항상 같은 객체를 반환한다.

### 5. 게임 개발 예시

GameManager 하나가 게임 점수, 현재 스테이지, 일시정지 여부 같은 전역 게임 상태를 관리하도록 만들 수 있다.

### 6. 간단한 Lua 예제

```lua
local GameManager = {
    score = 0
}

function GameManager:addScore(value)
    self.score = self.score + value
end

-- 이 테이블 하나를 모듈로 반환해서 모두가 공유한다고 생각하면 된다.
GameManager:addScore(100)
print(GameManager.score)
```

### 7. 장점

- 객체가 하나만 존재함을 보장하기 쉽다.
- 공용 관리 객체에 접근하기 편하다.
- 전역 자원을 한곳에서 관리할 수 있다.

### 8. 단점

- 전역 변수처럼 남용하기 쉽다.
- 코드 간 결합도가 커질 수 있다.
- 테스트에서 객체를 독립적으로 분리하기 어려울 수 있다.

### 9. 핵심 키워드

`하나의 인스턴스`, `전역 접근`, `Manager`, `공유 상태`, `Instance`

### 10. 헷갈리기 쉬운 패턴

Singleton은 **객체 생성 개수를 하나로 제한**하는 것이 핵심이다. 단순히 전역 변수 하나를 만든 것과 비슷해 보이지만, 설계 목적은 인스턴스의 유일성과 접근 방식을 관리하는 데 있다.
